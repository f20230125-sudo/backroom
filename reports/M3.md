**M3 — Names, reconciliation, e-invoicing, database and pipeline**

Implemented and verified on 27 October 2026. M1, M2 and M3 gates pass. The oracle engine check finds all 31 planted problems with zero false alarms; this is **not an extraction result**. The recording-based evaluation finds 21, leaves 10 not run, and reports 11 false alarms.

**Files and behavior**

- `backroom/config.py`: Decimal tolerances, contract commission rates, VAT rates.
- `backroom/names/{normalise,match}.py`: Unicode/case/punctuation and legal-form normalization, exact keys, rapidfuzz candidates, conservative auto/review/new proposals, optional offline grey-band model recommendation, explicit `approve(...)` / rejection. Proposals cannot resolve identities. Existing decisions survive reloads and rebuilds.
- `backroom/recon/{types,payouts,ledger,engine}.py`: statement net arithmetic, commission contract and commission VAT, bank receipts, daily platform gross and refunds versus POS, POS versus ledger journals, bills by canonical supplier and invoice number with amount checks, duplicate invoices, invoice line/VAT/total arithmetic. Messages include AED amounts and calendar week labels. Unknown identities remain review dependencies rather than generating missing-bill/link assertions.
- `backroom/einvoice/rules.py`: IBR-132-AE and IBR-128-AE ports, mandatory fields and line fields, supplier masters, shared registrations, supplier-scoped original credit-note links. Findings identify document/master record type, identity and rule.
- `backroom/db/{repo,__init__,__main__}.py` and `migrations/001_init.sql`: all 20 SPEC tables, forward-only atomic migrations, keys/unique constraints, parameter binding and an allowlisted SQL identifier adapter. SQLite defaults to `.local/backroom.sqlite`; PostgreSQL uses `DATABASE_URL`. CLI connection errors withhold details.
- `backroom/inputs.py`: parsed CSV feeds, saved ExtractionResult ingestion, offline extraction fallback, cache opened using SQLite `mode=ro`. A live JSONL file is read once; its complete-line prefix is the snapshot. Missing rows stay not run. No model fallback occurs for missing rows when a recording file exists.
- `backroom/pipeline.py`: watermark windows, full and partial runs, rebuild, extraction issues/quotes/status, name proposals, review dependencies, reconciliation, master/document findings and run logs. Late missing recordings are retried even after the feed watermark reaches the end. Failed runs roll back business changes and retain a safe failure audit. Saved historical model-call counts do not count as new provider calls.
- `eval/m3.py` and `eval/run_eval.py`: names precision/recall/F1 and five bidirectional hard-negative challenges; source-linked found/missed/not-run/false-alarm counts by kind. Document detection consumes extracted records; truth supplies the answer key only. Tests repair a planted error only in the extracted record and inject an unplanted error to prove scoring does not copy truth.
- `backroom/m3_gate.py`, `backroom/verify.py`: cumulative M3 gate and explicitly labelled oracle records/approvals confined to temporary gate databases.
- `tests/test_{names,recon,einvoice,pipeline,m3_eval}.py`: unit checks, SQLite full/incremental/rebuild/rollback/idempotency integrations, pipeline followed by offline evaluation on a fake saved extraction, read-only cache checks, partial-recording and late-arrival checks, and PostgreSQL integration when `DATABASE_URL_TEST` is provided.
- `eval/results.json`: actual saved-recording evaluation, including M3 sections.

No protected source/data files were edited. The extraction runner and record mode were not run. There were no package installs or network requests. Existing tests and gates write generated fixtures only under `.local/`.

**Decisions, deviations and remaining limits**

- Exact canonical master names/IDs resolve directly. Fuzzy names require an approved mapping for identity-dependent checks even when their proposal says auto_match. Oracle tests explicitly approve truth variants in disposable databases; production ingestion never does that.
- ISO subdivision aliases in the synthetic fixtures (`DU`, `AZ`, `SH`, `UQ`, `FU`, `AJ`, `RK`) explicitly map to the seven PINT-AE codes before validation. This preserves the reference rule while accepting the M1 master representation.
- Scheduling uses only manifest issue dates/week dates; no truth amounts, names, tax facts or problem flags enter document detection. Held-out source text was consumed only by evaluation, not inspected or used for rule tuning.
- The last weekly statement closes on 4 October. The terminal 30 September load includes that partial business week and its later bank receipts; earlier incremental windows defer bank-shortfall checks until the payment date. Otherwise a literal end-date cutoff would silently omit six final statements.
- Real run logs intentionally contain real timestamps and durations and add one row per run. Business-table idempotency excludes those audit rows on same-database reruns. Two independent empty-to-full gate runs compare **all** tables, including audit rows, with injected fixed clocks/timers. Rebuild preserves approvals and run history.
- Monetary facts are lossless Decimal strings in portable TEXT columns and JSON payloads. SQL does not perform floating-point money arithmetic. Python checks parse source amounts as Decimal and round half-up only at monetary boundaries.
- Draft/brief/ask/inbox tables are provisioned for later milestones; drafting, brief generation, Ask and inbox webhook processing remain M4/M5 work. No messages are sent.
- PostgreSQL SQL and adapter paths are implemented, but no PostgreSQL server was exercised because `DATABASE_URL_TEST` was not supplied. No PostgreSQL pass is claimed.
- The recording is still in progress. The saved evaluation and local database describe the snapshots above; they are not final extraction results. Rerun offline ingestion/evaluation after recording completes. No claim of full end-to-end detection accuracy is made.
