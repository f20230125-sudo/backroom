# M2: document agent

Implemented offline, without network calls or a real key. L4/E2 source content was not opened or printed. Existing M1 byte-determinism checks hash all generated artifacts, including held-out files, without extracting their content. Only dev invoices/emails and payout sources were inspected during implementation.

## Files and behavior

- `backroom/extract/text.py`: pdfplumber reading order and logical table rows, including wrapped descriptions; MIME headers, preferred plain body, inert HTML-to-text fallback, and PDF attachments. Maximum file size: 5,242,880 bytes. Maximum combined PDF pages: 10. Default parser deadline: 20 seconds in a killable subprocess. No renderer, browser or network fetch.
- `classify.py`: content/header/attachment signals first; schema-constrained model fallback only for ambiguous content. Paths, layout names and manifest truth do not enter classification or extraction.
- `prompts/invoice_v1.md`, `prompts/payout_v1.md`: versioned prompts, document delimiters, explicit injection guard, decimal strings, exact quotes, null missing facts.
- `agent.py`: extraction, validation, at most one repair; source-backed findings retained. Repairs cannot erase findings by changing supported facts. Missing recordings become explicit `not_run` reviews. Malformed/hostile JSON, unsupported quotes, instruction-derived evidence and unsupported notes cannot be accepted.
- `validate.py`: pure quote presence/value checks, including line fields; normalized evidence matching; line-net sum, 5%/all-zero VAT, total, TRNs, date ordering, signed payout arithmetic and payout dates. Pydantic parses calendar dates before typed validation.
- `rules.py`: comparison baseline authored against L1-L3/E1 labels and tables only; includes signed credit notes and dev original-reference labels.
- `payouts_csv.py`: strict A/B dialect headers, metadata consistency, dates, service rows, final totals and Decimal values; no model.
- `schema.py`, `types.py`: flattened provider schemas, issues and extraction metadata. `PayoutRecord` subclasses `PayoutStatement` to add evidence and annotations.
- `run.py`: offline default, explicit `--record`, `--limit`, `--doc`; sorted-key JSONL in gitignored `data/out/extractions.jsonl`; status/cache/call counts.
- `eval/run_eval.py`: independent extraction section for later milestones; per-document states, agent/baseline and dev/held-out/payout splits, field/line accuracy, review share, accepted-but-wrong, classifier and security scoring. Sorted JSON keys and one `generated_at`. Added `--exclude-held-out` as a development safeguard.
- `backroom/models.py`: nullable invoice/payout line facts and invoice credit-note flag preserve missing values. Complete M1 records remain byte-identical. Extraction payout metadata also permits null.
- `backroom/settings.py`: offline construction never reads `.env`; model selection can use process `GEMINI_MODEL`. Online behavior is behind explicit recording in the new commands.
- `backroom/verify.py`: cumulative M2 gate, including planted truth-value checks, dev baseline, prompts, offline miss and every A/B statement value.
- `tests/test_extract.py`, `tests/test_extract_eval.py`: fake-provider router/cache, repair, malformed/hostile output, missing facts/quotes, arithmetic boundaries, PDF/MIME/HTML limits, CSV dialects, deterministic evaluation, held-out read guard, CLI and gate failure checks.
- `pyproject.toml`: pytest temporary files remain inside `.local/temp/`.
- `eval/results.json`: actual offline dev-only evaluation. `cache/llm.sqlite` was initialized locally with no recorded model responses and no real key.

No real-model extraction accuracy or production security success is claimed. Fake-provider tests verify suspicious flags with unchanged business fields/status and that hostile responses route to review.

Business field accuracy excludes `quotes`, `notes`, `suspicious_instruction` annotations. Security separately compares every business field/line value with unchanged ground truth, requires the suspicious flag, and checks the status implied by ground-truth missing fields/arithmetic. Accepted-but-wrong uses scored records with status `accepted` as its denominator. Cache misses do not enter accuracy or review-share denominators; omissions are counted explicitly. Line matching tries order first, then one-to-one complete matches; duplicate predictions cannot match a truth line twice.

## Exact schemas sent

These are byte sizes of the actual schema objects alone, excluding the enclosing request and prompt. Compact HTTP encoding uses `json.dumps(schema, ensure_ascii=False, separators=(',', ':'))`. Canonical cache encoding uses `json.dumps(schema, ensure_ascii=False, sort_keys=True)` including spaces.

| Pydantic model | Compact HTTP UTF-8 bytes | Canonical cache UTF-8 bytes |
|---|---:|---:|
| InvoiceRecord | 1979 | 2167 |
| PayoutRecord | 1635 | 1796 |
| Classification | 292 | 318 |

Definitions are inlined: no `$ref` or `$defs`. Decimal fields use string/null schemas and are parsed to Decimal; numeric JSON money is rejected. Titles, defaults, Decimal regex patterns and `additionalProperties=false` are removed for compatibility. Typed string-valued quote maps remain. Local models still forbid unknown fields.

## Deviations, limits and open questions

- Full held-out evaluation and real-model accuracy remain unmeasured. The senior engineer can run `python -m backroom.extract.run --record`, followed by `python -m eval.run_eval --offline`; that eval defaults to all layouts. Neither command was run online here.
- Live Gemini schema acceptance cannot be verified without network/key. Fakes verify the exact schema reaches the existing provider/router. No package installation is needed.
- The 5% rule follows SPEC literally: all-zero lines permit zero VAT; otherwise use 5% of net. Mixed zero/standard-rated lines would need a separately agreed rule.
- Platform C daily rows have no printed id. The exact service-day text becomes the extracted row id, explicitly requested in the prompt and supported by its quote. The generator's private row id is not guessed. Payout line accuracy compares the seven substantive line fields, excluding synthetic ids.
- File/parser failures route to review with an issue. Invalid schemas/calendar dates yield `OUTPUT_INVALID` and at most one repair. Null missing facts remain available when the rest of the record parses.
- Baseline scope is L1-L3/E1. Dev fixes included wrapped descriptions and existing credit-reference labels. No rules or prompts were tuned against held-out source output. The baseline deliberately has no PDF_C extractor.
- The runner overwrites its JSONL with the selected subset. The smoke run contains DOC-001's explicit cache miss. Incremental persistence is M3 work.
- Security evaluation uses unchanged synthetic truth and its expected status rather than an extra unrecorded model ablation. Annotation differences are expected; business facts and status must match.
- Existing M1 generation/hash checks cover all artifacts as required. M2 source inspection, baseline development and the executed eval excluded L4/E2 document content.
