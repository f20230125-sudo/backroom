Implemented files and behavior:

- `backroom/names/normalise.py`: field-specific item pack/unit/condition cleanup,
  regular plural spelling, TRDG and S&S expansion, and token-order equivalence.
  Product distinctions such as red/baby/sparkling and accessories remain meaningful.
- `backroom/names/match.py`: entity-type candidate filtering, unique significant-token
  containment, ambiguity safeguards, scored review suggestions, and recorded checks.
  Supplier identity uses a valid TRN belonging to exactly one master, then approved
  or deterministic auto name evidence, then a namespaced normalized printed name.
  Shared TRNs never choose a supplier; rejected name evidence stays excluded.
- `backroom/pipeline.py`, `backroom/recon/types.py`, `backroom/recon/engine.py`,
  `backroom/recon/ledger.py`, `backroom/ask/projection.py`, `backroom/ask/tools.py`,
  `backroom/einvoice/rules.py`: use the same supplier identity for invoice/bill keys,
  duplicate detection and spend deduplication, credit-note links, and supplier queries.
  Unknown printed names can group documents without being inserted as master IDs.
- Reconciliation templates now name the accounting fact being compared and retain
  the actual amounts; payout short/over amounts use natural wording. E-invoice
  missing-field labels are readable, and missing credit references no longer print
  an invented `(missing)` invoice. The missing-bill template is
  `Invoice X from <supplier> for AED Y has no matching bill in the ledger.`
- `eval/m3.py` and `eval/results.json`: replay recorded name checks, score model-yes
  review proposals according to SPEC 5.2, and report suggestion accuracy separately.
- `backroom/names/run.py` and `README.md`: the senior's recorder and offline replay.
  The runner persists observed proposals plus evaluation variants and records both
  hard-negative directions. No approvals are changed. Model suggestions with weak
  lexical evidence are limited to masters of the field's type, then require a separate
  binary check and remain review proposals. There is no synonym lookup table.
- `backroom/m3_gate.py`: independent M3.1 identity/name-evidence checks wired into the
  existing `backroom.verify m3` and cumulative `m4` gates.
- Regression coverage in `tests/test_names.py`, `tests/test_recon.py`,
  `tests/test_m3_eval.py`, `tests/test_ask.py`, and `tests/test_einvoice.py`: PR-021-shaped
  legal/trade names, shared and invalid TRNs, name fallbacks, persisted auto/approved/
  rejected names, field scoping, pack sizes, ambiguous containment, product accessories,
  suggestion-only vs model-yes scoring, semantic selection, and offline cache misses.

Policy details and remaining limits:

- The milestone explicitly authorizes deterministic auto-name evidence for supplier
  identity; this extends SPEC 3's original approval-only identity policy. Model review
  recommendations still do not apply merges. Existing approval/rejection statuses
  survive proposal refreshes and rebuilds. Other pending name proposals remain in
  the approval queue, including deterministic auto proposals not yet approved.
- Containment retains conservative guards for a bare name also present in another
  entity type (for example a shared location), and for product/accessory distinctions.
  These preserve the requested ambiguous names and hard negatives. Suggestions are
  always drawn only from the field's entity type. Regular plural rules and discarded
  pack/condition annotations can collide in broader catalogues; exact typed matches
  require a unique master, and containment counts distinct masters, not aliases.
- Weak lexical names may receive a recorded model suggestion before a binary check;
  this extends the initial fuzzy-only candidate path so synonyms are reachable without
  hardcoded equivalences. No claim is made about unrecorded model accuracy or recall.
- Saved extraction errors remain: dev accepted-but-wrong is 4/114 scored accepted
  invoices, and held-out is 1/23; these are unchanged from the baseline. Raw L4/E2
  outputs were not inspected for rule or prompt development. Verification and eval
  scored held-out data as required.
- Offline Ask has 30 in-scope questions not run because recordings are absent and
  five out-of-scope questions refused; the M4 gate validates the engine separately.
- `git diff` reports no changes to `backroom/extract/`, `backroom/llm/`,
