# M4 — Ask, drafts, brief and evaluation

Implemented offline, without invoking extraction recording or using a real model provider.
The extraction/model/settings sources, cache and data were not edited by this work. Existing
recorder changes in protected paths were left alone. No commits, network calls or secret-file
reads were performed.

## Implementation

- `backroom/ask/tools.py`: six closed, parameterised tools with strict Pydantic arguments,
  canonical/approved identity resolution, quarter date bounds, ISO weeks and `n <= 20`.
  Every response contains `tool_call_id`, `tool`, `args`, `rows`, `totals`. Unknown arguments,
  names, channels, platforms, kinds and tools are rejected. The registry is immutable.
- `backroom/ask/projection.py`, `backroom/db/migrations/002_ask.sql`, `backroom/db/repo.py`:
  portable invoice header/line projections and integer-fils columns for exact SQL aggregation.
  Projections use extracted records and approved mappings, not ground-truth invoice values.
  Duplicate supplier/invoice identities are excluded from spend; signed credit notes reduce it.
- `backroom/ask/agent.py`, `numbers.py`: structured calls/answers, four total model responses,
  one numeric repair within that budget, then refusal. Explicit scope refusals run before
  model use. Questions and tool results are escaped inside delimited data blocks. Numeric
  citations must refer to actual returned evidence; supplier/description injection text
  cannot supply quantitative evidence. Money, counts, percentages, number words, decimal
  shorthand and scientific notation are checked. Tolerance is applied against original
  values, avoiding compounded citation rounding.
- `backroom/ask/gold.py`, `eval/ask_gold.json`: 30 operator questions, five per tool,
  covering all three outlets and platforms. Two questions require two calls. Expected values
  come from separate fixed SQL queries. Five further questions require refusal.
- `backroom/drafts.py`, `backroom/brief.py`: schema-constrained wording, facts appended by
  code, numeric and identifier checks, stored drafts only, and a brief of at most 120 words.
  Invoice queries include VAT, line-sum, duplicate, invalid-TRN and unlinked-credit findings;
  open review items receive missing-information chases. Cache misses store explicitly marked
  `template (model not recorded)` artifacts. Model wording failures also fall back to templates.
- `backroom/pipeline.py`: projects SQL facts, produces drafts and one brief before measuring
  the completed run. Brief history survives rebuilds. The M3 idempotency test now compares
  business tables separately from the required per-run briefs and verifies brief counts.
- `eval/m4.py`, `eval/run_eval.py`, `eval/assumptions.json`: Ask correct/refused/wrong/not-run
  accounting, assumptions and formula, and measured full-run duration read from `run_log`.
  An existing pipeline DB is read without modification; evaluation does not silently create
  a new timing sample. The existing M2 security-plant implementation remains the sole scorer.
- `backroom/m4_gate.py`, `backroom/verify.py`, `tests/test_ask.py`, `tests/test_drafts.py`:
  strict argument/name checks, immutable registry, package transport scan, number checks,
  fake-provider repair/refusal/injection/step-limit tests, SQL expectations, signed credits,
  offline templates, brief limits, and hours-estimate checks.

Food cost means received food-category invoice line net divided by POS net sales; there is
no inventory-consumption feed. Top items ranks purchased invoice items by net spend; POS
has no menu-item detail. Unmatched item descriptions retain their source text, with the
single-category synthetic supplier master used as a category fallback. No fuzzy proposal
is approved automatically.

No real-model Ask or wording accuracy is claimed. The requested recording commands are
implemented but were not run with `--record`:

```text

python -m backroom.drafts --record
```

Run the M4 pipeline first to populate the normal database. Both recording commands also
accept `--database PATH`; Ask regenerates its SQL gold file before recording. Offline
replay is the default. PostgreSQL integration remains unverified here because
`DATABASE_URL_TEST` was unavailable.
